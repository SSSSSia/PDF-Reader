# 开发流程管理（Development Process）

> 用途：定义"一个阶段从启动到交付"的标准循环。AI 助手与人类开发者均须遵守。
> 配套：`重构路线图.md`（阶段定义）、`版本规划.md`（分支与发版）、`阶段文档模板.md`。

---

## 1. 阶段开发循环（八步，严格执行）

```
① 读路线图定位阶段 → ② 读阶段文档明确任务 → ③ 切分支 → ④ 逐任务开发
→ ⑤ 自测（验收标准 + 编译门禁）→ ⑥ 回填完成记录 → ⑦ 人工验收 → ⑧ 合并打 tag
```

1. **① 定位**：打开 `重构路线图.md` 第 4 节状态跟踪表，找到第一个非 ✅ 的阶段。
2. **② 明确任务**：读该阶段文档第 3 节任务分解；按 T 编号顺序执行（任务间有依赖时按文档标注）。
3. **③ 切分支**：`git checkout dev && git pull && git checkout -b phase-N`（N = 阶段号）。
4. **④ 开发**：逐任务实现，勾选阶段文档内对应 checkbox；发现范围外问题记录到"遗留问题"，**不扩权顺手改**。
5. **⑤ 自测**：跑该阶段文档第 4 节验收标准逐条验证 + 编译门禁（见第 3 节）。
6. **⑥ 回填**：填写阶段文档第 7 节完成记录（日期、文件清单、验收结果、性能对比、遗留问题）。
7. **⑦ 人工验收**：用户按人工测试清单操作确认；不通过则回到 ④ 修复，**验收通过前不得合并**。
8. **⑧ 合并发版**：`dev → master` 合并，按 `版本规划.md` 打 tag（阶段 1 = v0.4.0，依次类推）；更新路线图状态表为 ✅。

## 2. 提交规范

沿用 `版本规划.md` 第 4 节：`feat:` / `fix:` / `docs:` / `refactor:` / `chore:`，建议带任务编号：

```
feat: 前端渐进渲染，轮询即回传 pages（阶段1-T1）
fix: AsyncClient 复用消除 TLS 握手开销（阶段1-T3）
docs: 回填阶段1完成记录
```

## 3. 编译与测试门禁（每次提交前）

| 检查 | 命令 | 何时必须 |
|------|------|----------|
| 前端类型 | `npx tsc --noEmit` | 任何前端改动 |
| 前端构建 | `npx vite build` | 发版前 |
| Rust 检查 | `cd src-tauri && cargo check` | 任何 Rust 改动 |
| 后端单测 | `python -m pytest backend/tests/ -q` | 纯函数模块（见第 4 节） |
| 后端语法 | `python -m compileall backend/ -q` | 任何后端改动 |

> 注：Rust 构建需要 Windows 10/11 SDK 环境（见开发总纲第 10 章已知限制）；当前开发机 `cargo check` 已可通过。

## 4. 测试策略

**原则**：纯函数上单测（快、稳、防回归），链路靠人工测试清单（LLM API 不适合自动化冒烟）。

### 4.1 后端单测（pytest，随阶段扩充）

| 模块 | 已有/新增时机 | 覆盖点 |
|------|--------------|--------|
| `ocr/siliconflow.py::split_into_blocks` | 阶段 1 补 | 空行切段、空输入、无空行整段 |
| `ocr/textlayer.py::_clean_html` | 阶段 1 补 | `<br>`/`<sup>`/注释/实体清理 |
| `translate/providers/openai_compat.py` 批量解析 | 阶段 2 补 | `<<<n>>>` 标记解析、段数不匹配路径 |
| `cache/file_cache.py` 键生成 | 阶段 2 补 | 键含 prompt_version 后的隔离 |
| 术语抽取 JSON 解析 | 阶段 2 补 | 容错（非法 JSON / 缺字段降级） |
| 跨页合并规则 | 阶段 2 补 | 终止符/结构标记边界 |

测试文件放 `backend/tests/`，命名 `test_<模块>.py`；不发起任何网络请求（mock httpx）。

### 4.2 人工测试清单（每阶段必填，模板）

```markdown

- 测试日期：
- 测试 PDF：<文件名/页数/类型（文本层|扫描）>
- [ ] 上传 → 原文可见耗时：__s
- [ ] 译文开始流入耗时：__s / 全部完成耗时：__min
- [ ] 双栏对齐目测（截图）：
- [ ] 术语一致性抽检（阶段 2 起）：
- [ ] 深色模式过检：
- [ ] 结论（通过/退回 + 备注）：
```

### 4.3 冒烟脚本（可选）

保留一个 `scripts/smoke.py`：起后端 → 提交测试 PDF → 轮询到 done → 输出统计（缓存命中、耗时）。阶段 1 建议顺手写掉，便于后续每阶段回归。

## 5. 文档治理

1. 状态唯一源：`重构路线图.md` 状态跟踪表；任何状态变化当天更新。
2. 阶段文档回填时机：自测通过后、人工验收前（验收人需要看到完整记录）。
3. 契约变更：改总纲 4.x 数据模型/接口 → 先改总纲 → 再写代码（约束先行）。
4. 新决策：凡涉及选型/范围/接口的不可逆选择，以 D6+ 编号追加到总纲第 9 章。
5. 文档冲突时优先级：总纲 > 路线图 > 阶段文档（`README.md` 第 3 节）。

## 6. AI 助手协作要点

- 开工注入顺序：`docs/README.md` → `重构路线图.md` → 当前阶段文档 → 本文件。
- 任务指派格式："执行阶段 N 任务 T-x"（可多任务并指）。
- 阶段完成的汇报必须包含：勾选状态、验收结果、完成记录已回填、路线图状态已更新。
- 上下文延续：跨会话看 `.workbuddy/memory/` 日志（按日期倒序读最近 1–2 天即可）。
