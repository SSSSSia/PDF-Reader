# 版本规划（Versioning & Release Plan）

> 用途：让后续开发与「开源复刻」有清晰的版本节奏。本文件与 `docs/开发总纲.md` 配套，
> 总纲定「做什么 / 不做什么」，本文件定「怎么发版 / 怎么迭代」。

## 1. 分支模型

| 分支 | 用途 | 说明 |
|------|------|------|
| `master` | 稳定可发布版本 | 只接受来自 `dev` 的合并，每次合并打 tag |
| `dev` | 日常开发 | 所有新功能 / 缺陷修复先合入 `dev` |
| `feature/*`、`fix/*` | 短期任务分支 | 从 `dev` 切出，完成后合回 `dev`（PR 或本地 merge） |

当前初始提交已落在 `master`，并已打 `v0.1.0`。开发新功能前请先 `git checkout dev`。

## 2. 版本号（语义化版本 SemVer）

`主版本.次版本.修订`：
- **主版本**：架构级不兼容变更（如换技术栈、换分发方式）
- **次版本**：新增可见能力（如新增 provider、新增导出、暗色模式）
- **修订**：缺陷修复 / 小改动

| 标签 | 对应阶段 | 内容 |
|------|----------|------|
| `v0.1.0`（已打） | Phase 0 + Phase 1 部分 | 主链路打通、OCR 重写、缓存、配置热更新、缩略图 |
| `v0.2.0`（规划） | Phase 2 | provider 抽象（D3）、暗色模式、拖拽上传、导出双语 Markdown/TXT |
| `v0.3.0`（已实现，待打 tag） | Phase 3 | 测试+CI、LICENSE(MIT)、`.env.example`、README 复刻指南、构建串联；待 Windows 10/11 SDK 环境 `cargo check` 复核后打 tag |
| `v0.4.0`（已实现，待打 tag） | 重构阶段 1 | 渐进呈现与性能：原文秒开、译文逐段流入、连接复用、job 生命周期（见 `重构路线图.md`） |

### 2.1 v0.8.0+ 候选池补充（2026-09-08 验收期结论）

验收期确认"提取/排版接近设计上限，下一阶段重心转向质量上台阶与功能扩展"，以下按性价比排序入池：

| 候选项 | 性质 | 依据 |
|--------|------|------|
| 翻译模型 A/B 与升级 | 质量上台阶 | 当前 Qwen3-8B 是速度/成本妥协；翻译质量是当前最大单点瓶颈（问题句翻一半、术语不稳）。同篇论文双模型对比后决定 |
| 视觉结构校验 | 架构增强 | 文本层提取后用低倍率整页渲染让视觉模型比对结构，只修结构不动字符——把两条路线优势合并，进一步压提取长尾 |
| 文档库/首页 | 功能扩展 | ✅ 已立项为重构阶段 6（v0.8.0），见 `阶段6-文档库与持久化统一.md` |
| WebView2 STATUS_BREAKPOINT 治理 | 稳定性 | 渲染进程崩溃未定位到应用侧根因（GPU 驱动/WebView2 Runtime 嫌疑），必要时加 `additionalBrowserArgs` 对照试验 |

数据支撑：`docs/提取质量体检.md`（6 篇论文结构残留 0.00%）、`docs/文本层vsOCR对比.md`（文本层字符保真 0.854 vs OCR 0.649，OCR 有静默空输出/幻觉/漏段失败模式）——混合架构（文本层字符保真 + 结构规则 + 视觉按块兜底）成立，不推倒重来。

## 3. 里程碑（Milestones ↔ Phase）

- **M1（v0.1.0）已完成**：应用可用——选 PDF → OCR → 翻译 → 双语对照 + 缩略图导航。
- **M2（v0.2.0）**：扩展与体验——多 provider、导出、暗色、拖拽。
- **M3（v0.3.0）**：工程化与开源就绪——CI、文档、一键复刻。

## 4. 提交规范（Commit Message）

- `feat:` 新功能　`fix:` 缺陷修复　`docs:` 文档　`chore:` 构建/依赖　`refactor:` 重构
- 例：`fix: useOcr 轮询回显流水线状态（R1）`、`feat: 引入 pdfjs-dist 缩略图导航（D4）`

## 5. 发布（Release）检查清单（每次打 tag 前）

- [ ] `npx tsc -b` 与 `npx vite build` 通过
- [ ] 在具备 Windows 10/11 SDK 环境 `cargo check` 通过（当前开发机缺失，见总纲第 10 章）
- [ ] `scripts/build-backend.ps1` 产出 sidecar 成功
- [ ] `npm run tauri build` 产出自包含 exe
- [ ] `config/config.json`、API Key 等私密文件未被提交（已写入 `.gitignore`）
- [ ] 更新 `docs/开发总纲.md` 的路线图状态

## 6. 开源复刻友好性

- README 必须写明：依赖（Python 3.11+、Node 20+、Rust 工具链、Windows 10/11 SDK）、
  构建步骤、`APPDATA/pdf-reader/config.json` 配置项、如何填 SiliconFlow API Key。
- `config/config.json`（无 Key 的模板）可入库作为示例；真实带 Key 的 `config.json` 已被 `.gitignore` 排除。
- LICENSE 在 M3 补充（已确认 **MIT**，见仓库根 `LICENSE`）。
