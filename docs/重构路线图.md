## 1. 重构目标（可量化）

| 维度 | 现状 | 目标 |
|------|------|------|
| 首次可见时间 | 全文翻译完才有任何内容（2–4 分钟） | 文本层 PDF 上传后 **≤ 3 秒**可见全文原文 |
| 译文呈现 | 一次性 | **逐段渐进流入**，边译边读 |
| 术语一致性 | 同一术语跨批次漂移 | 抽检 5 个术语全文译法一致 |
| 双栏对齐 | 字符数估算，错位漂移 | 左右**结构化同行对齐**，零漂移 |
| 稳定性 | _jobs 内存泄漏、截断静默降级 | 连续 10 份 PDF 内存平稳、截断自动重试 |

## 2. 总原则

1. **渐进式重构，不推倒重来**（决策 ADR-R0）：现有栈（Tauri/React/FastAPI/文本层优先/合并批量）经审计 80% 正确，推倒重写是负收益。
2. **每阶段独立可交付**：阶段结束 = 可用版本 + tag + 回填文档，任何时刻停下项目都处于可用状态。
3. **感知优先**：先解决"用户看得到的"（渐进呈现），再解决"用户感受到的"（质量），最后解决"天花板"（渲染路线）。
4. **遵守总纲约束**：不改锁定选型；阶段 4 若要走原生渲染，属新决策 **D6**，必须由用户确认后方可动工。

## 5. 阶段门禁（每阶段必须全部满足才算完成）

1. 阶段文档内所有任务 checkbox 勾选（或明确标注放弃 + 原因）。
2. 验收标准逐条通过（阶段文档定义的可量化指标）。
3. 人工测试清单填写完毕（模板见 `开发流程管理.md`）。
4. `npx tsc --noEmit` + `cargo check`（有 Rust 改动时）通过。
5. **完成记录回填**到阶段文档（日期、文件清单、遗留问题）。
6. 合并 `dev → master`，打 tag（按 `版本规划.md` 语义化版本）。

## 6. 风险清单

| 风险 | 影响 | 缓解 |
|------|------|------|
| 轮询全量 pages 的载荷随文档增大 | 网络与渲染压力 | 阶段 1 先按 1s 轮询上线；若大文档卡顿，阶段 2 提供 SSE 替代 |
| 术语抽取多一次 LLM 请求 | 成本与首译时延 +1 请求 | 术语表按 pdf_hash 缓存，仅首次；失败时降级为无术语表直译 |
| 跨页段落合并误判 | 段落错误拼接 | 保守规则（仅句尾无终止符且下页非结构块时合并），合并处留日志 |
| KaTeX 对 pymupdf4llm 输出无效（公式非 LaTeX 源） | 公式改善有限 | 阶段 3 只承诺 `$...$` 语法可渲染；根治在阶段 4 决策 |
| 阶段 4 立项后工程量超预期 | 排期失控 | 决策门设计：先 1–2 天原型 spike 拿数据，再定立项 |
