## 1. 背景与证据

- 后端 `processor.py:197` 已提前挂载 `job["pages"]` 并逐段原地更新译文——渐进能力**后端已具备**。
- 前端 `useOcr.ts:50-53` 只在 `status === "done"` 时才 `setPages`，轮询数据全丢；`isLoading` 全屏遮罩（BilingualPage/InlinePage）挡住一切。

## 2. 范围

## 3. 任务分解

- [x] **T1 前端渐进渲染**（`src/hooks/useOcr.ts`）
  - 轮询循环内：只要 `status.pages` 非空就 `setPages(status.pages)`（每次轮询都更新）。
  - 去抖：仅当内容实际变化时 setState（可比较已译 block 数或 progress 值，避免每秒重渲染长文档）。
  - `done`/`failed` 分支保留（设置 result / error）。
  - 完成：`progressiveSignature()`（页数/总块/已译块三元签名）去抖；新增 `unknown` 状态显式报错（后端 job 淘汰/重启场景）。
- [x] **T2 去掉全屏遮罩，改顶部进度条**
  - `BilingualPage.tsx` / `InlinePage.tsx`：删除 `if (isLoading) return <LoadingSpinner/>` 门控（pages 为空时才显示空态提示）。
  - 新增/复用一个非阻塞进度条（阅读页顶部，随 progress 移动，`status==="done"` 后隐藏）。
  - `MainPage.tsx`：跳转时机从"全部完成"提前到"pages 首次非空"（OCR 完成、progress ≥ 30），让用户尽快进入阅读页看原文。
  - 完成：跳转由 `navigatedRef` + pages 就绪 effect 驱动；`processFile` 不再 await（轮询闭包持 zustand setter，组件卸载后仍回传）；两阅读页新增非阻塞进度条 + 错误横幅。
- [x] **T3 AsyncClient 连接池复用**（`backend/translate/providers/openai_compat.py`）
  - 模块级懒加载单例 `get_client() -> httpx.AsyncClient`（首次调用时创建，超时 120s）。
  - `translate()` 内改用单例，**不再** `async with` 关闭它。
  - 注意：单例绑定事件循环，uvicorn 单循环下安全；进程退出时无需显式关闭。
- [x] **T4 `_jobs` 生命周期管理**（`backend/pipeline/processor.py`）
  - 容量上限（如 50 个 job）+ TTL 淘汰（如完成 2 小时后删除）；超额时淘汰最旧已完成项。
  - 运行中 job 不可淘汰；淘汰逻辑在 `run_pipeline` 入口处执行即可。
  - 完成：`_evict_jobs()`（TTL 2h + 容量 50，只淘汰 done/failed）；done/failed 时记录 `finished_at`。
- [x] **T5 验证后端渐进行为 + 页级流式增强**
  - 确认 `get_pipeline_status` 在翻译过程中返回部分译文的 pages（现状应已满足，写一个最小冒烟验证：跑一份 2 页 PDF，翻译中途 curl status 观察部分 translated）。
  - 完成：新增 `backend/tests/smoke_progressive.py`；实施中把 OCR 阶段从"整篇提取后一次挂载"升级为**页级流式挂载**（`textlayer.extract_pages` 逐页提取，`_load_or_run_ocr` 逐页 append 到 `job["pages"]`，扫描页挂空占位保持页序）。两次冒烟均 SMOKE PASS。

## 4. 验收标准（全部满足才算完成）

> **修订说明（2026-09-06 实测）**：原标准 #1「上传后 ≤3 秒**全文**原文可见」基于
> "文本层提取毫秒级"的错误假设——实测 pymupdf4llm 布局分析约 0.5s/页
>（表格检测为主，线程并行无效：GIL）。据此修订为"首页 ≤2s + 全文按时长档"，
> 并将实现从"整篇提取后挂载"升级为"页级流式挂载"（T5 增强）。

1. **首页原文 ≤2 秒可见**；全文原文（12 页文本层 PDF）≤ 20 秒内渐进挂载完成（实测 1.7s / 17.2s）。
2. 译文渐进出现：进入阅读页后已译段数持续递增（实测 10→30→60→…→124 逐档流入）。
3. 12 页论文全量翻译总时长 ≤ 2 分钟（中文目标实测 97.7s；日语目标冒烟 325s，属语言差异与高峰波动，记录备查）。
4. 连续处理 10 份 PDF 后，`_jobs` 条目数 ≤ 上限（日志验证）。
5. `npx tsc --noEmit` 通过；无 Rust 改动则 `cargo check` 可豁免。
6. 人工测试清单（`开发流程管理.md` 模板）填写完毕。

## 9. 范围扩展记录二（人工验收反馈，2026-09-06）

用户反馈三条：①图片没提取出来，要 URL 形式原样显示在页面中；②翻译把页码也翻进去了；③UI 没有原 PDF 论文的质感。

- **①图表快照管线**（`backend/ocr/textlayer.py`，`TEXT_LAYER_MODEL` → `text-layer-v3` 使旧缓存失效）：
  - 根因：该 PDF 的图为**矢量图**（LaTeX/matplotlib 导出），无法作为图片文件提取；栅格图又被 pymupdf4llm 拆成碎图无引用。唯一可行方案是**区域快照**。
  - 实现：`_figure_regions` 检测「栅格图 rect + `cluster_drawings` 矢量簇」→ `_merge_rects` 合并 → `page.get_pixmap(clip=, matrix=2.5x)` 高清截图 → `_insert_figures` 按 caption 锚定插回 markdown（图在上、注在下）。
  - **关键修复**：初版用"区域文本 <200 字符"过滤表格，误杀了矢量图表——其轴标签/图例是真实文本（实测 860–1534 字符）。改为 `page.find_tables()` 精确排除表格（重叠 >30% 即排除），文本上限放宽到 2000 作兜底；caption 锚定只匹配 Figure/Fig/图（Table 不做快照不占锚位）。
  - 实测（GraphRAG-Bench.pdf）：page2 1 图 + page9 2 图全部正确落盘并锚定；表格页 0 误报；全文 12 页提取 12.7s（含快照，符合"全文≤20s"修订标准）。
- **②页码噪音过滤**（`backend/ocr/siliconflow.py`）：`_NOISE_BLOCK` 过滤独立纯数字 / 罗马数字 / `Page x of y` 行，不再进入翻译块；`backend/pipeline/processor.py` 同时跳过纯图片块的翻译（图表引用原样保留，`translated = original`）。
- **③论文质感**：`index.css` 新增 `.paper-font`（Georgia/Times/思源宋体系衬线）；两种阅读模式原文/译文列加 `paper-font + text-justify` 两端对齐；图表块整行居中（`<figure>`，双语模式）或独立展示（紧跟模式）。
- **图片 URL 化**：markdown 中图片引用为本地绝对路径，`assetUrl`（`src/lib/bridge.ts`）转换——Tauri 模式走 `convertFileSrc`；**浏览器模式新增兜底**走后端新增 `GET /api/asset?path=`（`backend/main.py`，realpath 校验限制在 cache_dir 内防任意文件读取）。
- **门禁**：`tsc --noEmit` / `vite build` / `compileall` / `pytest 32/32`（含新增 `test_figures.py` 4 例）全绿。
