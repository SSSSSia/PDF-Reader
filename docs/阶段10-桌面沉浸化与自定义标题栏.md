# 阶段 10：桌面沉浸化——自定义标题栏与全屏阅读（v0.12.0）

> **状态**：📋 已立项，待 mockup 确认后启动（2026-09-10 用户提出） ｜ **前置**：无强依赖（可与阶段 9 并行；UI 改动按约定先出 mockup） ｜ **依据**：用户需求 2026-09-10（参照靠岸学术 Scholaread：自绘标题栏、内容铺满全屏；及 2026-09-09 反馈"感觉还是在看浏览器页面"）
> **目标一句话**：去掉系统标题栏，把应用名/文档名/拖拽区/最小化/最大化/关闭做进界面（Scholaread 式），内容区通顶铺满整个窗口——强化"原生桌面软件"的观感，阅读视图不再被 ~170px 的界面 chrome 挤压。

---

## 1. 背景与证据

- 用户反馈（2026-09-09）："这个桌面端软件怎么感觉还是在看浏览器页面一样"——系统标题栏 + 大面积页面 chrome 是主因之一（当时已给出方案：自定义标题栏，用户 2026-09-10 确认执行）。
- 用户参照（2026-09-10 Scholaread 截图）：窗口顶部一条自绘栏承载 logo/文档名/功能按钮/窗口控制钮，内容区从栏底直接通顶铺满，无任何系统边框。
- 现状：Tauri 默认系统标题栏；阅读区容器 `h-[calc(100vh-170px)]`（顶栏+工具条占 ~170px），小屏上阅读面积损失明显。

## 2. 范围

**做**：`tauri.conf.json` `decorations:false`；自绘 TitleBar 组件（左：应用名+当前文档名；中/右：工具区迁移评估 + 最小化/最大化/关闭，`data-tauri-drag-region` 拖拽）；内容区布局通顶改造（170px 常量 → 实测 flex 布局）；窗口控制接 `@tauri-apps/api/window`；双击标题栏最大化、边缘语义保留。
**不做**：窗口透明/异形/贴边吸附等花活；多窗口管理改造；Linux 深度适配（以 Windows 为目标平台）。

## 3. 任务分解

- [ ] **T1 mockup（前置 gate，用户确认后开工）**：自绘标题栏视觉稿（浅色/深色两态，含文档名超长截断、按钮 hover 态）
- [ ] **T2 窗口配置与权限**：`decorations:false`；确认 Tauri 2 window 权限（minimize/maximize/close/startDragging）在 capability 清单放行
- [ ] **T3 TitleBar 组件**：`src/components/TitleBar.tsx`——拖拽区、窗口控制三钮（hover 语义色，关闭 hover 红）、双击最大化切换；顶部工具条内容评估迁移（文档名进标题栏后原位置释放）
- [ ] **T4 内容区通顶改造**：`h-[calc(100vh-170px)]` 等硬编码高度收敛为 flex 通顶（`h-screen` 链）；三种阅读形态 + 设置页回归
- [ ] **T5 验收与回归**：四种阅读形态/设置/暗色模式全过；缩放、左右对照联动不受影响；**顺带复验阶段 7 T5**（重排版双栏 grid 在缩放下的列宽/换行——本阶段改了内容区布局，基线已变，合并复验避免二次回归）；pytest/tsc/build 通过

## 4. 验收标准（全部满足才算完成）

1. 窗口无系统标题栏；自绘栏可拖拽移动、双击最大化、三钮工作正常（关闭 hover 红色语义）。
2. 阅读内容区从自绘栏底直接通顶到窗口底，无系统边框与多余留白；小窗口下阅读面积较改造前增加 ≥100px 高度。
3. 四种阅读形态、设置页、暗色模式无布局破碎；文档名超长在标题栏省略号截断。
4. 重排版双栏在 70%–200% 缩放下列宽/换行正常（阶段 7 T5 并入本条验收）。
5. `npx tsc --noEmit`、`npx vite build`、`pytest` 全过。

## 5. 风险与缓解

| 风险 | 缓解 |
|------|------|
| WebView 顶层元素（下拉菜单/弹层）与自绘栏层级冲突 | TitleBar 用普通文档流（非 fixed），弹层 z-index 约定复核 |
| 无边框窗口失焦态视觉不明确 | 失焦时标题栏文字降透明度（桌面软件惯例） |
| `decorations:false` 后窗口阴影/圆角丢失 | Windows 下 Tauri 默认保留阴影；异常时 shadow 选项显式开启 |
| 硬编码高度散落多处 | T4 一次性收敛为 flex 链 + 集中常量，grep 复查 `calc(100vh` |
