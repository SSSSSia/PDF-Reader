# 阶段 2：翻译质量工程（v0.5.0）

> **状态**：🚧 开发完成待验收（2026-09-07） ｜ **前置**：阶段 1 完成 ｜ **依据**：瓶颈分析报告 §3
> **目标一句话**：术语全文一致、截断不再静默降级、缓存随提示词演进、段落跨页完整。

---

## 1. 背景与证据

- `_system_prompt` 零文档上下文（`openai_compat.py:25`）→ 术语跨批次漂移、代词指代丢失。
- `translate()` 不查 `finish_reason`：10 段合并输出截断 → 段数不匹配 → 静默回退串行（慢且无感知）。
- 翻译缓存键 `(text_hash, lang, model)` 无提示词版本（OCR 侧有 v2 版本控制，翻译侧没有）→ 改提示词旧缓存仍命中。
- `_split_page` 按页切块 → 跨页段落被切成两块，紧跟模式同段显示两次残文。

## 2. 范围

**做**：可靠性三件套（finish_reason / 缓存版本 / 合并）+ 术语表两遍法 + 可选 SSE。
**不做**：排版与对齐（阶段 3）、渲染路线（阶段 4）、provider 扩展（总纲 Phase 3 范畴）。

## 3. 任务分解

- [x] **T1 finish_reason 检查 + 自动减半重试**（`backend/translate/providers/openai_compat.py`）
  - `translate()` 返回时检查 `choices[0].finish_reason`；为 `length` 时视为批次失败。
  - `translate_batch()` 内：段数不匹配或截断时，**将 chunk 减半重试**（10→5→2→1），而不是直接串行回退；单段仍失败才落空并记日志。
  - 日志格式：`[translate] 批次截断，减半重试 chunk=N→M`。
- [x] **T2 翻译缓存键版本化**（`backend/cache/file_cache.py` + `pipeline/processor.py`）
  - `translate_key()` 增加 `prompt_version` 参数；`openai_compat.py` 定义 `PROMPT_VERSION = "v2"` 常量，提示词或参数（temperature 等）变更时必须手动升版。
  - 与 OCR 侧 `TEXT_LAYER_MODEL = "text-layer-v2"` 的既有做法对齐。旧缓存自然失效（不迁移）。
- [x] **T3 跨页段落合并**（`backend/pipeline/processor.py`，`_split_page` 之后加后处理）
  - 保守规则：前一页最后一个 block 不以终止符（`. ! ? : 。！？：`）结尾 **且** 下一页第一个 block 不以结构标记（`#`、`|`、`![`、列表符、数字编号）开头 → 合并为一个 block，归属前一页。
  - 每次合并打日志（页码对），便于回查误合并。
  - 注意与翻译缓存的关系：合并后段落文本变化 → text_hash 变化 → 旧缓存自然不命中，符合预期（一次性成本）。
- [x] **T4 术语表两遍法**（新模块 `backend/translate/glossary.py` + processor 接线）
  - Pass 0：取文档标题（第 0 页首个 `#` 标题）+ 摘要 + 首批段落（截断到 ~3000 字符），单次 LLM 请求抽取 10–30 个关键术语及推荐译法，输出 JSON。
  - 缓存：按 `(pdf_hash, model)` 落盘（复用 file_cache，键如 `glossary:<hash>`）。
  - Pass 2：`_system_prompt` 注入术语表 + 论文标题；`openai_compat.translate_batch` 传入可选 `glossary` 参数（config 或调用参数，注意别破坏总纲 4.3 接口契约——以可选参数扩展，默认 None 保持兼容）。
  - 失败降级：术语抽取失败 → 记日志，直接走无术语表翻译（不阻塞主链路）。
- [ ] **T5（可选，时间允许）SSE 流式推送**（未实施：轮询方案满足需求，留作长文档增强）
  - 新端点 `GET /api/pipeline/stream/{job_id}`（text/event-stream），前端 useOcr 优先用 SSE、轮询兜底。
  - 仅在轮询全量 setPages 在长文档（>30 页）上出现卡顿时实施，否则跳过并记录原因。

## 4. 验收标准

1. 术语一致性：选一篇含领域术语的论文，抽检 5 个术语，全文译法一致（人工抽查）。
2. 截断重试：人为把 `max_tokens` 调小复现截断，观察日志出现"减半重试"且最终段数完整、无静默串行。
3. 缓存版本：升 `PROMPT_VERSION` 后重跑同一 PDF，翻译缓存 0 命中（stats 验证）。
4. 跨页段落：选一份段落跨页的 PDF（正文连续无标题分隔），紧跟模式中该段落显示为一个完整块。
5. 术语抽取失败降级：临时填错 Key 跑术语抽取 → 主链路仍正常出译文（日志含降级记录）。
6. `npx tsc --noEmit` 通过；若动了 Rust 侧命令签名（不应动），`cargo check` 必须通过。

## 5. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 术语抽取请求失败/超时 | 30s 超时 + 降级直译；结果按 pdf_hash 缓存，重试成本低 |
| 合并规则误判（如页脚接正文） | 保守条件 + 日志；阶段验收时人工核对合并点 |
| 减半重试放大请求次数 | 仅在截断/不匹配时触发，正常路径零开销；单段兜底仍有 |
| 提示词注入术语表后 token 上升 | 术语表限 30 条以内，每条一行 |
