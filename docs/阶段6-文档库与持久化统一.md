# 阶段 6：文档库与持久化统一（v0.8.0）

> **状态**：🔶 开发完成待人工验收（2026-09-09，T1–T7 全部完成，含验收期扩展 T5–T7） ｜ **前置**：阶段 5 验收通过（可并行启动 T1） ｜ **依据**：用户需求 2026-09-08（API Key 只填一次 / 主页文章列表 / 缓存路径统一）+ 验收期用户反馈 2026-09-09（靠岸学术参考排版 / 文件夹管理 / 崩溃诊断）
> **目标一句话**：翻译过的文章在主页可查可一键重开；API Key 只需配置一次；所有用户数据收敛到同一目录。

---

## 1. 背景与证据

- 用户反馈（2026-09-08）：启动前后端都要设置一遍 API Key（输入框有默认值但流程上仍要确认），开源复刻场景必须"只填一次"。
- 配置现状：后端单一来源已是 `%APPDATA%/pdf-reader/config.json`（`backend/config.py`），但前端 `configStore` 存在本地缓存轨（localStorage），存在双轨不同步的可能（待 T1 排查确认）。
- 缓存现状：正式路径 `%APPDATA%/pdf-reader/cache/`（config.json + cache/），`~/.pdf-reader/` 仅无 APPDATA 环境变量时兜底（2026-09-07 会话已梳理）——用户要求所有持久化明确收敛到用户数据目录。
- 文档索引缺失：管线结果纯内存（`processor.py` `_jobs` + TTL 淘汰），重启后主页无从展示，只有散落的缓存键值（无文档归属）。

## 2. 范围

**做**：配置单一来源与一次填写、持久化文档索引、主页列表页（点击重开已译文档）、缓存/配置路径统一确认、源文件丢失的降级策略。
**验收期扩展（2026-09-09，用户反馈驱动）**：界面改版对齐"靠岸学术"参考——侧边栏布局、文件夹管理（前后端）、卡片缩略图、空态、返回导航修复；删除二次确认与崩溃可诊断性（详见 T5–T7）。
**不做**：翻译模型 A/B 与质量升级（入候选池）；视觉结构校验（候选池）；缓存格式改造（保持现有 KV 结构，仅加索引层）。

## 4. 验收标准（全部满足才算完成）

1. 删除 `%APPDATA%/pdf-reader/` 后全新启动：配置 API Key **一次** → 翻译一篇 → 完全重启应用 → 不再出现任何 Key 填写/确认提示，直接可翻译。
2. 主页展示所有翻译过的文档（≥3 篇测试样本），显示标题与翻译时间；点击任一篇 **≤3 秒** 打开已译内容（缓存命中，无新的翻译 API 调用）。
3. 源 PDF 被移动/删除后：对照/紧跟模式仍可打开（缓存内容完整），原版模式给出明确的"源文件缺失"提示且不崩溃。
4. config.json、cache/、docs_index.json 位于同一用户数据目录；`~/.pdf-reader/` 不再产生新文件（兜底轨仅在无 APPDATA 环境时激活）。
5. 界面改版（T5/T6，2026-09-09 验收期扩展）：侧边栏含文献库导航 + 文件夹分组（新建/重命名/删除/计数）；点侧边栏文件夹进入 `/folder/:folderId` 视图，空文件夹显示「共 0 篇文献」+ 搜索框 + 空态提示；卡片缩略图小尺寸居中不整卡满铺；翻译途中点「文献库」/「← 返回」停留在文献库不被弹回阅读页，翻译完成自动进入阅读页的正常流程不受影响。
6. 删除文件夹弹应用内确认对话框（非 window.confirm），确认后执行、Esc/取消不执行；其中文献回未分类。
7. React 渲染崩溃显示错误详情 + 重新加载按钮（非白屏/一句话）；未捕获异常落盘 `数据目录/logs/frontend.log`。
8. pytest 全过、`npx tsc --noEmit` 与 `npx vite build` 通过。

## 5. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 源文件丢失后打开体验差 | 打开前校验 file_path；对照模式纯缓存可用是兜底主路径，原版模式禁用+提示 |
| 索引与缓存不一致（缓存被清、索引残留） | 打开时按 pdf_hash 校验缓存关键页存在，缺失则降级为"重新翻译"引导 |
| docs_index.json 并发写坏 | 单进程后端 + 原子写（tmp+rename），与 file_cache 同模式 |
| 打包版 sidecar 工作目录与开发版不同 | T1/T4 用打包版实机验证路径（列入人工测试清单） |
